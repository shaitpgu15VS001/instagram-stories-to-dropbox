📖 מדריך שימוש מורחב – הכל, מאפס

מדריך זה עומד בפני עצמו: מה זה גיטהאב, איך פותחים הכל, ואיך מפעילים כל אפשרות – בשפה פשוטה. לממהרים יש גם מדריך קצר.

מדריכים: התקנה (קצר) שימוש מורחב פתרון בעיות

0. מילון – כל המילים במקום אחד

מילההסבר פשוט
GitHub (גיטהאב)אתר שמאחסן קבצים ומריץ תוכנות בחינם, 24/7. הרובוט שלנו גר שם – המחשב שלך יכול להיות כבוי.
ריפו (Repository)תיקיית הפרויקט שלך בגיטהאב. שם יושבים הקוד, הרשימות וההגדרות.
Branch (ענף)גרסה של הריפו. הענף הראשי נקרא כמעט תמיד main. אנחנו עובדים תמיד עליו.
Commit (שמירה)כפתור ירוק ששומר שינוי שעשית בקובץ באתר. בלי לחיצה – לא נשמר כלום!
Actions / Workflowה"רובוט": הוראות אוטומטיות שגיטהאב מריץ. שלנו נקרא Download Instagram Stories to Dropbox.
Run workflowכפתור להפעלת הרובוט עכשיו, בלי לחכות לשעה האוטומטית.
Secret (סוד)כספת מוצפנת בגיטהאב לסיסמאות. אף אחד – גם לא אתה אחרי השמירה – לא רואה את התוכן.
Token (אסימון/מפתח)סיסמה ארוכה שתוכנה נותנת לך כדי שתוכנה אחרת תוכל לפעול בשמך. מתנהגים אליו כמו לסיסמה.
rcloneתוכנת-מתווך חינמית בין המחשב לעננים (Dropbox, OneDrive...). מתקינים פעם אחת.
APIדלת כניסה ממוחשבת לשירות – במקרה שלנו, הדרך שבה cron-job.org אומר לגיטהאב "תרוץ עכשיו".
cron / לוח זמניםשעון מעורר אוטומטי – למשל "כל 3 שעות". שעון גיטהאב עובד לפי UTC (ראה סעיף 5).
state (זיכרון)קובץ קטן שזוכר מה כבר הועלה, כדי לא להעלות פעמיים. עובר לבד בין הרצות – לא נוגעים.
סטורי פעילסטורי מה-24 שעות האחרונות. אחר כך הוא נמחק מאינסטגרם לתמיד – אי אפשר לשחזר.
לוגיומן ההרצה, שורה אחרי שורה. כשמשהו לא עובד – קוראים שם (ובסוף יש טבלת סיכום).

1. גיטהאב מאפס (פתיחה, ריפו, העלאת קבצים)

1.1 פתיחת חשבון

1. היכנס ל-github.com/signup.
2. מלא כתובת מייל אמיתית (תקבל אליה קוד אימות), סיסמה חזקה ושם משתמש באנגלית. פתור את החידה (לוודא שאתה אדם).
3. הכנס את הקוד מהמייל. בחר תוכנית Free (דלג על שאלות סקר – אפשר ללחוץ Skip).
4. זהו – יש לך חשבון. שמור את הסיסמה במקום בטוח.

1.2 יצירת ריפו (מקום לפרויקט)

1. לחץ github.com/new (או + למעלה ← New repository).
2. שם באנגלית, למשל instagram-stories. תיאור – לא חובה.
3. בחר Private (מנעול – רק אתה רואה). אל לסמן "Add a README". לחץ Create repository.

1.3 העלאת קבצי הפרויקט (בלי להתקין כלום)

1. בדף הריפו לחץ Add file ← Upload files.
2. אם קיבלת קובץ ZIP – חלץ אותו קודם לתיקייה במחשב (לחיצה ימנית ← חלץ הכל).
3. גרור את תוכן התיקייה (את הקבצים, לא את התיקייה העוטפת!) לאזור ההעלאה. חכה שהכל יעלה (100%).
4. למטה לחץ Commit changes (ירוק). בדוק שהקבצים מופיעים ברשימה – למשל usernames.txt, README.md, תיקיית src.
דרך חלופית למתקדמים: תוכנת Git + שורת פקודה (git init/add/commit/push). לא חובה – ההעלאה מהדפדפן מספיקה לגמרי.
חשוב: ודא שהענף הראשי נקרא main (כתוב למעלה ליד שם הריפו). כל ההוראות מניחות כך – כולל ה-dispatch החיצוני ({"ref":"main"}).

2. חיבור ענן (rclone) – פעם אחת

2.1 התקנה

Windows: פתח PowerShell (חיפוש "PowerShell" בהתחל) והדבק winget install rclone + Enter. אם אין winget – הורד מ-rclone.org/downloads. Mac: brew install rclone. Linux: curl https://rclone.org/install.sh | sudo bash.

2.2 חיבור Dropbox

1. ב-PowerShell: 
rclone authorize "dropbox"
2. יופיע קישור (או קוד) – פתח בדפדפן, התחבר ל-Dropbox, לחץ Allow לאישור גישה.
3. חזור ל-PowerShell – מופיע קוד ארוך (token). אל תסגור את החלון.

2.3 חיבור OneDrive (אופציונלי – רק אם רוצים ענן שני)

אותו רעיון: rclone authorize "onedrive" --auth-no-open-browser, אישור בדפדפן בחשבון Microsoft, שמירת הקוד.

2.4 שמירת החיבורים בקובץ

1. הרץ rclone config. לכל ענן: הקש n ← שם באנגלית קטנה (dropbox) ← בחר את הסוג מהרשימה במספר ← פעמיים Enter (שדות ריקים) ← N ← הדבק את הקוד מצעד 2/2.3 ← y. בסוף q.
2. בדוק שהחיבור עובד: 
rclone lsd dropbox: --config "$env:USERPROFILE\.config\rclone\rclone.conf"
אם רואה תיקיות – מחובר!
3. פתח את הקובץ והעתק הכל: 
notepad "$env:USERPROFILE\.config\rclone\rclone.conf"
(ב-Mac/Linux: cat ~/.config/rclone/rclone.conf).

2.5 ה-Secret היחיד בגיטהאב

1. בריפו: Settings ← שמאל: Secrets and variables ← Actions ← New repository secret.
2. שם: RCLONE_CONF. תוכן: כל מה שהעתקת בצעד הקודם. Add secret.
כלל ברזל (אבטחה): את קובץ rclone.conf עצמו אסור להעלות לריפו – רק דרך ה-Secret! מי שמקבל את הקובץ מקבל גישה לענן שלך. אם חושדים בדליפה – לבטל גישה בהגדרות הענן ולחבר מחדש.

3. אנשים למעקב

שלוש דרכים (אפשר לשלב). המומלצת למתחילים: טקסט.

3.1 טקסט – צעד אחר צעד

1. בריפו לחץ usernames.txt ← עיפרון ✏️.
2. שורה לכל אדם, בלי @: 
israel_bidur
natgeo
3. רוצה תיקייה בעברית? שם תצוגה, קו |, שם משתמש: 
ישראל בידור | israel_bidur
4. Commit changes (ירוק). בלי זה – לא נשמר!
איך יודעים שהחשבון ציבורי? פתח אותו בדפדפן בחלון אנונימי (Ctrl+Shift+N) בלי להתחבר – רואים פוסטים = ציבורי. "This account is private" = לא יעבוד, אל תוסיף.
מותר גם: עם @ (@natgeo) או קישור מלא לפרופיל – המערכת מבינה לבד. שורות שמתחילות ב-# הן הערות ומתעלמים מהן.
שינוי שם תצוגה יוצר תיקייה חדשה – הישנים נשארים במקומם. מחיקת שורה עוצרת מעקב אבל לא מוחקת קבצים מהענן.

3.2 טעויות נפוצות (לקרוא לפני שמתלוננים 😊)

  • שכחתי Commit – השינוי לא נשמר. תמיד ללחוץ ירוק בסוף!
  • רווחים/שורות ריקות – לא מזיקות, מתעלמים מהן.
  • אותו אדם פעמיים (גם בקבצים שונים) – המערכת מסירה כפילויות לבד.
  • שם עם שגיאת כתיב – יופיע בדו"ח כ"לא נמצא". תקן את האיות.

3.3 CSV ואקסל (למתקדמים)

usernames.csv: שורת כותרת username,display_name ואז שורות. usernames.xlsx: עמודה A = שם משתמש, B = שם תצוגה (שורה 1 = כותרות). קידוד CSV בעברית: לשמור כ-UTF-8 (ב-Excel: "CSV UTF-8").

4. קבצים והחלטות ⭐

4.1 מאילו אנשים להוריד

  • רק ציבוריים שמעניינים אותך. חשבון מת יופיע כ"לא נמצא" – נקה מתים פעם בחודש.
  • כמות: כל אדם כמה שניות. 10 ≈ דקה-שתיים, 400+ ≈ שעה-שעתיים.

4.2 לאיזה ענן לחבר

  • חבר ענן עם מקום פנוי. כמה עננים? אפשר – ותבחר ביניהם בסעיף הבא.
  • אחרי כל שינוי ב-rclone.conf – חובה להדביק מחדש ל-Secret!

4.3 לאיזה ענן להוריד (כולל מילוי אוטומטי)

ב-STORAGE_BACKEND.txt – שורה לכל ענן לפי סדר:

dropbox
onedrive
  • מעלים לראשון שיש בו מקום (מתחת ל-97%). נגמר? עוברים לבא בתור לבד, גם באמצע – כתוב בלוג "עובר ענן מ-X ל-Y".
  • ראשון = הענן הנוח לך. השאר = רזרבה. קובץ הזיכרון תמיד בראשון.
  • הכל מלא? ההרצה עוצרת עם הודעה. פנה מקום/הוסף ענן והרץ שוב – מה שלא עלה ינוסה שוב לבד.
  • מבנה: Instagram/תאריך/שם-תצוגה/קבצים. שמות: user-YYYY-MM-DD_HH-MM-SS.jpg/mp4 (שעון ישראל).

4.4 לא לגעת (אבל טוב להכיר)

  • state.json בענן (.instagram-sync/) – הזיכרון. עובר לבד.
  • .github/workflows/sync.yml – הגדרות הרובוט.
  • src/ – הקוד. מקור: insta-stories.io (ראשי), fastdl.app (גיבוי).

5. הרצה

5.1 אוטומטית

כל 3 שעות, לבד. כלום לעשות.

5.2 ידנית (כפתור)

1. Actions למעלה (אם כתוב שה-workflows כבויים – אשר).
2. שמאל: Download Instagram Stories to Dropbox.
3. ימין למעלה: Run workflow → שוב Run workflow. אופציות: force_redownload (הכל מחדש), storage_backend (ענן אחר לפעם זו).
4. לחץ על ההרצה ← sync – לוג חי. ראשונה: 3-5 דקות (התקנות).

5.3 מי מעורר – GitHub או חיצוני מדויק

קובץ SCHEDULE.txt, שורה אחת: trigger=github (ברירת מחדל – שעון גיטהאב + כפתור, לא מדויק לדקה) או trigger=external (שירות חיצוני דרך API, דיוק ~דקה; שעון גיטהאב מדולג לבד; כפתור תמיד עובד).

cron-job.org (חינמי), צעד אחר צעד:

  1. טוקן: תמונת פרופיל בגיטהאב ← Settings ← Developer settings ← Personal access tokens ← Fine-grained tokens (לא classic!). Generate new token: שם (למשל cron-job-stories), תוקף 1 year (שים תזכורת לחדש!), גישה רק לריפו הסטוריז, הרשאת Actions → Read and write. Generate ← העתק מיד.
  2. הירשם ל-cron-job.org ← בדשבורד Create cronjob. 3 לשוניות: COMMON, NOTIFICATIONS, ADVANCED.
  3. COMMON: Title לזיהוי. URL (החלף USER/REPO): https://api.github.com/repos/USER/REPO/actions/workflows/sync.yml/dispatches. מתג Enable job דולק. לוח זמנים: Custom עם 0 */3 * * *, בדוק ב-Next executions. Schedule expires כבוי.
  4. ADVANCED: Request method = POST. Request body: {"ref":"main"} (או שם ה-branch שלך). Headers ← ADD: Accept=application/vnd.github+json, Authorization=Bearer הטוקן. Time zone = Asia/Jerusalem.
  5. NOTIFICATIONS: הדלק התראה על כשלון (Notify after 1 failure).
  6. לחץ TEST RUN ובדוק שנוצרה הרצה בטאב Actions. רק אז CREATE.
שגיאת 401 ב-TEST RUN = בעיית טוקן/כותרת: שתי הכותרות הוגדרו? הערך בדיוק Bearer רווח טוקן? הטוקן לא פג? (פרטים: פתרון בעיות).

אזורי זמן (שלא יהיו אי-הבנות)

  • שעון גיטהאב = UTC תמיד. כל 3 שעות בדקה 0 = 03:00, 06:00... ישראל (קיץ).
  • cron-job.org – חובה Asia/Jerusalem, אחרת UTC.
  • תיקיות וקבצים = ישראל. לוגים = UTC (הוסף 2-3 שעות).

1. היכנס לענן ← Instagram ← תאריך היום ← שם.
2. בסוף כל לוג יש RUN SUMMARY – טבלה:
שורהמה זה אומרמה לעשות
STORIES_FOUNDנמצאו והועלו. מצוין!לבדוק בענן.

NO_NEW_STORIESהכל כבר הועלה. תקין.כלום.

7. תחזוקה – כל הפעולות

  • הוספה/הסרה: שורה בקובץ ← Commit. קבצים ישנים נשארים בענן (מחיקה ידנית בלבד).
  • מעבר ענן: ערוך STORAGE_BACKEND.txt ← Commit. להעתקת ישנים: הרצה ידנית עם force_redownload=true.
  • תדירות (שעון גיטהאב): ב-sync.yml שנה cron: '0 */3 * * *' (0 */1 * * * שעתי, 0 */6 * * * כל 6, 0 0 * * * יומי בחצות UTC). Commit.
  • ענן מתמלא: הוסף ענן שני או פנה מקום (מחק תיקיות תאריך ישנות שגיבית).
  • ניקוי מתים: פעם בחודש עבור על USER_NOT_FOUND בדו"ח ומחק.
  • טוקן cron-job פג (שנתי): צור חדש ועדכן במשימה (אותם צעדים כמו בהתחלה).

8. שאלות נפוצות

  • צריך אינסטגרם? לא. רואים שצפיתי? לא – אנונימי.
  • פרטי? לא עובד. רק ציבוריים.
  • פעמיים אותו סטורי? לא (הזיכרון מונע).
  • כמה מקום? תמונה ~חצי מגה, וידאו ~3-6 מגה. ראשונה גדולה, אחר כך רק חדשים.
  • ענן התמלא באמצע? עוברים לבא לבד. הכל מלא? עוצרים עם הודעה, מנסים שוב בהרצה הבאה – לא אבד.
  • כמה עולה? הכל חינמי (גיטהאב Free, ענן חינמי, cron-job חינמי). גבולות: 2,000 דקות הרצה בחודש בגיטהאב – מספיק בהחלט לשימוש רגיל.

9. מגבלות (ביושר)

  • רק ציבוריים – אין עקיפה.
  • תלוי בשירות חיצוני – נופל לפעמים, חוזר לבד תוך שעות.
  • שעת קובץ = דיוק דקות (מחושבת מ"לפני X שעות").
  • שעון גיטהאב לא מדויק לדקה – לדיוק: cron-job.org.
  • טוקן cron-job פג כל שנה – לחדש.
