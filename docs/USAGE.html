2. קבצים והחלטות המשתמש ⭐

סעיף זה מסביר אילו קבצים אתה עורך, ואיך להחליט.

2.1 מאילו משתמשים להוריד

קובץלמה הוא משמשמתי לערוך
usernames.txt / .csv / .xlsxרשימת החשבונות למעקבהוספה/הסרה של חשבון, שינוי שם תצוגה
  • איך להחליט: הוסף רק חשבונות ציבוריים שמעניינים אותך. חשבונות פרטיים לא יורדו לעולם.
  • שם תצוגה: אם שם המשתמש באנגלית ואתה רוצה תיקייה בעברית - השתמש בפורמט שם תצוגה | username. שים לב: שינוי שם תצוגה יוצר תיקייה חדשה, הקבצים הישנים נשארים במקומם.
  • הסרה: מחק את השורה. קבצים שכבר הועלו נשארים בענן (לא נמחקים).
  • כמות: אין מגבלה קשיחה, אבל כל משתמש לוקח כמה שניות. עשרות משתמשים = כמה דקות טובות.

2.2 לאיזה ענן לחבר (חיבורים)

Secret בשם RCLONE_CONF בריפועותק של rclone.conf לשימוש GitHubאחרי כל שינוי ב-rclone.conf - להדביק מחדש!
  • איך להחליט: חבר את הענן שבו יש לך מקום פנוי. אפשר לחבר כמה עננים בו-זמנית (Dropbox + OneDrive) ולבחור ביניהם בהמשך.
  • כלל ברזל: אף פעם לא להעלות את rclone.conf לריפו כקובץ - רק כ-Secret מוצפן.

  • מה קורה אם השם לא קיים: ההרצה נכשלת עם הודעה ברורה + רשימת החיבורים הזמינים. תקן את השם והרץ שוב.
  • מבנה התיקיות בענן: Instagram/<תאריך>/<שם תצוגה>/קבצים.

3. הרצה

אוטומטית

כל 3 שעות, ללא פעולה מצדך.

ידנית

Actions ← Download Instagram Stories to Dropbox ← Run workflow. אפשרויות:

  • force_redownload = true - מוריד ומעלה הכל מחדש, מתעלם ממה שכבר הועלה. שימושי אחרי מעבר ענן.
  • storage_backend - שם חיבור אחר להרצה זו בלבד.

4. בדיקה בענן

היכנס לענן ונווט ל-Instagram/<תאריך>/<שם>/. הקבצים נקראים username-YYYY-MM-DD_HH-MM-SS.jpg/mp4 (שעת ישראל).

5. תחזוקה ושינויים

  • הוספה: שורה חדשה בקובץ המשתמשים → Commit → הרצה.
  • הסרה: מחיקת שורה (קבצים ישנים נשארים בענן).
  • מעבר ענן קבוע: עדכן STORAGE_BACKEND.txt → Commit. הקבצים הישנים לא עוברים לבד - הרץ עם force_redownload=true אם רוצה להעתיק הכל.
  • שינוי תדירות: ערוך cron: '0 */3 * * *' ב-sync.yml. דוגמאות: 0 */1 * * * כל שעה, 0 */6 * * * כל 6 שעות, 0 0 * * * פעם ביום.

6. שאלות נפוצות

  • האם צריך חשבון אינסטגרם? לא.
  • האם זה אנונימי? כן - ההורדה דרך שירות חיצוני, בעל החשבון לא רואה שצפית.
  • חשבון פרטי? לא נתמך, רק ציבוריים.
  • אותו סטורי יועלה פעמיים? לא - state.json מונע כפילויות.
  • איפה הסטוריז נשמרים? רק בענן שלך, תחת Instagram/תאריך/שם/.

7. מגבלות ידועות

  • רק חשבונות ציבוריים.
  • תלוי בשירות חיצוני (insta-stories.io) - אם הוא נופל או מוסיף Captcha, ההורדה נכשלת עד לתיקון.
  • חותמות זמן מחושבות מזמן הפרסום היחסי (לפני X שעות) - דיוק של דקות.
  • מגבלת GitHub: בלי הגבלת זמן מוגדרת (ברירת המחדל של GitHub היא 6 שעות להרצה). שים לב לעקוב שהרצות לא נתקעות.

8. טיפים

  • הרצה ראשונה איטית (התקנת דפדפן ~150MB). הבאות מהירות.
  • לבדיקת תקינות: הוסף חשבון פעיל מאוד (למשל instagram) והרץ ידנית.
  • אחרי שינוי rclone.conf - תמיד עדכן את ה-Secret.
  • לוגי ההרצה מפורטים - חפש RUN SUMMARY בסוף.
